## C11 (AI の難しさの補い): 選んでもらうこと

光の遅れで AI の国が弱くなったかを、AI の国が本当の様子を見る版 (光の遅れなし: `seenBy` がいまの様子を返す・開戦をすぐ知る・指令がすぐ届く) と比べた。人間の国は観戦用の手 (光の遅れなしで本当の様子を見る) で動かした。32 の銀河 × 300 年 × 6 か国。測った道具は使い捨て (コミットしていない)。

| | 終わりの年の AI の国の数 | 人間の国の入植星系の割合 | 星系の取り合い: AI が取った / 人間が取った | 講和会議: AI の勝ち / 人間の勝ち |
|---|---|---|---|---|
| いま (AI も光の遅れ。#145 のあと) | 11.9 | 19.1% | 4 / 3 | 0 / 0 |
| AI に光の遅れなし (#145 のあと) | 12.3 | 18.3% | 2 / 3 | 0 / 1 |
| いま (#121 のあと、#145 の前) | 12.8 | 19.6% | 11 / 10 | 1 / 2 |
| AI に光の遅れなし (#121 のあと、#145 の前) | 12.8 | 18.6% | 12 / 7 | 1 / 0 |

- 光の遅れで、人間の国の取り分は 1 ポイントほど増える (AI が少し弱くなる) だけ。取り合いや講和会議は数が少なく、差は偶然の範囲
- ただし観戦用の手は本当の様子を見ている。本物のプレイヤーも古い情報で判断するので、プレイヤー相手なら AI はこの表よりさらに弱くならない

| 案 | 中身 | 見込み |

## 落とし穴

- **main がとても速く動く** (レーン B・C・P・Q・S・U が並行)。マージの直前に `git fetch origin main && git merge-base --is-ancestor origin/main HEAD` で確かめ、動いていたら取りこんで CI を回し直す。セッション 3 では #121 を 4 回取りこみ直した。
- ぶつかる場所はいつもセーブの行 (`buildSave`) と `index.html`。`index.html` は手で直さず `node tools/build.mjs` (先に `cd tools && npm ci`)。
- 目標の番号と版は、ほかのレーンも使う。出す直前に `targets/targets.json` の版と最後の番号を見る。
- 重い測定を裏で回しながら `node tools/ci-tests.js` を回すと、`rotate` が時間切れで落ちることがある (単独で回すと合格)。
- 物理の所 (`shieldOf`・`withAccel` など) と `EDITIONS.sim` はレーン P だけが触る。`simulation.html` は作り直さない (`docs/parallel.md` の 6)。
