# 回の分け方と、最初のメッセージ

2026-10-21 の再出発 (`docs/restart.md`) のあとの回の一覧です。レーンは「触るコードの場所」で分けた 6 つ (`docs/parallel.md` の 1)。どの回も、下の「最初のメッセージ」をそのまま送ります。どの文も「docs/session-start.md の 3 に従って」で始まり、約束・始め方・終わり方はそこにあるので、ここには「何をするか」だけを書きます。前のセッションの一覧 (セッション 1〜25・H・P・Q・S・U) は `docs/archive/sessions-2026-10.md`。

## 1. 順番の考え方 (Q2 = b。2026-10-21 のユーザーの決定)

- **最初の 2 時間と、光の遅れの見せ場を先に作る** (評論家の改造計画のフェーズ 0・1。`docs/critique/04-plan.md`)。返金の線 (2 時間) の内側を直さないと、ほかを積んでも遊ばれない。
- **面白さの物差しを先に作る**: 人間に近い遅れつきのボットと、面白さの代わりの数を F 系の目標にして、以後の回で毎回見張る。
- **英語と中国語の準備を先に**: 用語集と固有名詞の一覧は先に。文字列を集める本番は、ほかが止まっている時期に 1 本だけで。
- **現実の段 (経済政策・集団・年齢・船の設計) は止めずに、並行のレーンで進める** (2 波目から)。
- 中身の一覧は `docs/backlog.md` (B- の番号)。返事待ちは `docs/decisions.md` (QD- の番号)。

## 2. どの回でも同じ進め方

1. **自分のレーンのフォルダだけを直す** (`docs/src-files.md` の地図)。`src/core/` は登録の形か 1 行の呼び出しだけ (`docs/parallel.md` の 2)。
2. **目標を先に固定する**: その回で合わせる目標は、作る前に「目標の変更」の PR で決めて `node tools/check-targets.js --lock` で固定する。番号は `docs/registry.md` の自分のレーンの範囲から。
3. **補正なしで作って測る → 困ったら補正**: 遊びが崩れたら、`docs/game-plan.md` の補正の台帳に 1 行足して `EDITIONS.game` で補正する。「現実的」と「面白い」がぶつかる所は表にして `docs/decisions.md` に足す。
4. **CI で両方を見る**: 現実の目標と、面白さの代わりの数の両方が大きく崩れていないかを見てからマージする。
5. **PR は小さく**: 社会・物理の PR と補正の PR を分ける。ブランチを積み重ねない。
6. **終わったら**: `docs/backlog.md` のその行に「済み (#PR)」、`docs/status/<レーン>.md` を更新し、「## 済んだ回」に回の名前を 1 行足す (例: `- GA1 (#180)`)。終わらなかったら残りを `docs/wip/` と状態のファイルに残し、次の回の文の頭に「前のセッションの残りを先に片付けてから」と足す。
7. **ユーザーに決めてもらうこと**は、その場で聞かずに `docs/decisions.md` に足す。作業が止まるときだけ、1 つの Artifact でまとめて聞く。
