# 処理の速さ (2026-10-26)

ユーザーの依頼「ゲームの処理速度を 10 倍にして。ゲームの内容は一切変えないで」に対してしたことと、測った結果です。**試合の筋は 1 ビットも変えていない** (同じシード・同じ手順なら、どの節目の状態の要約 (hash) も前と同じ)。

## 1. 結果

| 測ったもの | 前 | 後 | 比 |
|---|---|---|---|
| ブラウザ (Chromium) で試合を 300 年進める時間 (6 か国・シード 1・2・3 の合計) | 44.6 秒 | 25.0 秒 | **×1.79** |
| 実際の画面で最高速 (年 64 年) にしたときの 1 秒あたりの年数 (2550 年ごろ) | 9.6 年 | 16.2 年 | ×1.68 |
| 同じく 2350 年ごろ | 13.0 年 | 21.0 年 | ×1.62 |
| 画面なしの版 (`tools/headless.js`。CI の自動対戦・測る道具) で 300 年 (シード 1) | 52.9 秒 | 約 12 秒 | **×4.4** |
| 星間マップの国境の層を描き直す時間 (実際の画面の 1 コマに占める割合) | 15% | 10% | — |

- 試合の筋が同じことは、10 の筋 (国家選択あり・なし、観戦・観戦なし、シミュレーション版、途中で保存して読み込み直して続ける筋を含む。150〜300 年) の節目ごとの hash で確かめた。ブラウザでも 300 年後の hash が前と同じ。
- 国境の層は、前と同じ絵になることを、同じ試合・同じ視点の canvas の画素で確かめた。
- `node tools/ci-tests.js` はすべて合格。

**10 倍には届いていない** (ブラウザで約 1.8 倍)。理由と、さらに速くする道は 3。

## 2. したこと

### 2.1 いちばん効いたもの: 物の形を固定する (JavaScript の JIT のため)

ブラウザの JavaScript (V8 など) は、物の「形」(値の名前と並び) ごとに速いコードを作る。試合 (Game) の物は、作ったあとから覚えておく表などの値が 20 ほど足され、そのたびに形が変わっていた。形が何度も変わるのを見た所 (`this.fertility(…)` のようなメソッドの呼び出しや `this.galaxy` の読み出し) は、遅い道 (megamorphic) に落ちて戻らず、メソッドの埋め込みもできなくなる。

途中で書き込む値を `GAME_LATE_FIELDS` (core/game-consts.js) にまとめ、constructor の始めに undefined で置くだけで、試合を回す時間が約 2 割減った。セーブは決まった項目だけを書くので、セーブの中身は変わらない。`tools/tests/shape.js` が足し忘れを見つける。

### 2.2 同じ値の計算し直しをやめる・使わない値を計算しない

| 所 | 前 | 後 |
|---|---|---|
| `yieldOf` (1 人あたりの産出) | 1 刻みに約 5000 回、毎回 国・技術・種族の倍率・統治体制・天体を引き直す | `yieldCtx` で入植地ごとに 1 回だけ引き、7 つの部門に使う |
| `wagesOf` | 同じ状態で 2 回 (研究と消費の所) | 1 回 (`incomeWith`) |
| `servShare(所得)` (exp と log) | 同じ所得で 1 刻みに 4〜5 回 | 入植地ごとに前の答えを覚える |
| `eduStep` | 人のいない区分のための平均 (20 区分ぶんの exp・log) を毎回全部 | その区分が要るときだけ |
| 採掘基地の産出 | 計画と生産で 2 回 | 1 回 |
| 交易の候補探し | 資源ごとに、売り手の記録・運ぶ年数の利子を引き直す | 売り手ごとに 1 回 (関税は元と同じ時点で初めて引く。AI の国の財政はセーブに入るため) |
| 荷の区間 (`rebuildTransit`) | 荷と資源ごとに | 同じ道のりの荷で使い回す |
| 遮蔽の黄金分割の探索 (`shieldOf`) | 入植船の費用を引くたびに 42 回 | 同じ引数なら答えを覚えて写しを返す |
| 中央銀行の国ごとの星系 | 国ごとに全部の星系を調べる (2 回) | 1 回で分ける (`systemsByRealm`) |

### 2.3 探し方と毎回の生成を変える

- 年の順に並んだ記録から「t 以前でいちばん新しいもの」を頭から探していた所 (`econSeen`・`cbRateAt`・`seenBy`) を二分探索に (同じ結果)。
- `realmOf` (1 刻みに 1.5 万回) は、ふつうの連鎖を `Set` を作らずにたどる (輪になった連鎖のときだけ前の数え方)。
- 毎刻みの一覧の掃除は、消えるものがなければ配列を作り直さない (`keepWhere`)。作り直すと、続く `keepGhosts` が全件で `Set` を作っていた。
- `routeBetween`・`reach` の印の文字列、`warKey` の文字列、`sysDist` の WeakMap、`lastPeace` の全件の探索、`fertility` の表を毎回作る所をなくした。
- 決まった計算 (DMath) の 2^k と 1/(2n+1) を始めに表にした (1040 万回の比べで、どの値も 1 ビットも同じ)。
- `economy` を、同じ順の `econ…` のメソッドに分けた (大きすぎて JIT の最適化に時間がかかり、外れやすかった)。

### 2.4 画面

- 国境の層: 升目の角ごとに近くの入植星系を探すとき、箱ごとに 1 回だけ並べる。升目ごとの配列・`Set`・`map` を作らない (描く順と値は前と同じ)。

### 2.5 画面なしの版 (`tools/headless.js`)

前は、グローバルの名前 (`Math`・`Set`・`Infinity` やゲームの関数) を引くたびに Proxy を通り、試合を回す時間の 6 割ほどがそれだった。ふつうのグローバルを持つ文脈 (`vm.constants.DONT_CONTEXTIFY`。Node 22.8 から) で動かし、知らない名前 (document など) だけをグローバルの prototype に置いた Proxy で受ける形にした。CI の自動対戦と測る道具が速くなる (古い Node では前の形で動く)。

## 3. 10 倍に届かない理由と、さらに速くする道

いまの時間は、特定の重い所がなく、ほぼ平らに散らばっている (いちばん重い関数でも全体の 5% 以下)。V8 の記録 (`node --prof`) で見ると、時間の 2〜3 割は「形がばらばらな物の値の読み書き」(megamorphic な読み書き) にかかっている。原因はデータの持ち方そのもの:

- 資源・帳簿・部門を名前で引く物 (`stock[r]`・`gv.ledger[k]`・`w[x]` など)。名前を変えながら同じ所で引くと、速い道を使えない。
- 政府 (`govs`) の物の形が 1 つずつ違い (5 つの試合で 885 通り)、41 の政府のうち 33 が遅い辞書の形になっている (値を `delete` しているため)。入植地も 24 通りの形がある。

ここから先は、どれも「試合の筋は同じでも、セーブの書き方 (JSON の鍵の並び) や、ほぼすべてのレーンのコードを変える」作り替えになる:

| 道 | 見込み | 変わること |
|---|---|---|
| 政府の物の形をそろえる (`delete` をやめ、始めから同じ並びで作る。読み込みでも同じ並びに入れ直す) | 約 1 割 | セーブの JSON の鍵の並び (中身は同じ)。`delete` と `undefined` の違いを見ている所の洗い出しが要る (試したら筋が変わった所があった) |
| 資源・帳簿を名前の物から番号の配列 (型付き配列) にする | 2〜3 割 | 経済・財政・交易のほとんどのコードと、セーブの読み書き (変換を挟む) |
| 試合の計算を Web Worker (別の CPU) に移す | 実際の画面で 1〜2 割 (描画と並べて動く) | 画面が試合の物をじかに読んでいる所を、写しを読む形に作り替える |
| 刻み (0.25 年) を粗くする・年 1 回の処理を間引く | 数倍 | **試合の筋が変わる** (今回の「内容を変えない」に反する) |

## 4. 測り方 (同じことをもう一度するとき)

- `node tools/bench.js` — いまの src と origin/main を同じシードで回し、時間と、節目ごとの hash が同じかを並べる (`--seeds`・`--years`・`--nations`・`--reps`)。
- `node tools/tests/shape.js` — 試合の物に、作ったあとから値が足されていないか。
- プロファイル: `node --cpu-prof tools/bench.js …` (関数ごと) や `node --prof` → `node --prof-process` (megamorphic な読み書きなど V8 の内側の時間)。ブラウザでは Playwright の CDP (`Profiler.start`) で取れる。
- 遅くしないための決まりは `docs/content.md` の 4。
