# 速さ (8 か国の試合が重い。依頼 2026-11-07 の common-1)

ユーザーの依頼 (`docs/requests/2026-11-07-common.md` の common-1):「8 カ国とかで回してると、すごく重くなる。処理速度を 10 倍にして、でもゲーム内容は一切変えないで」。

この文書は、何が重かったか・筋を変えずに何を直したか・直したあとも筋が同じことをどう確かめたか・10 倍に届かない理由と次の手を残す。

## 1. 決まり: 筋を 1 ビットも変えない

- 「ゲーム内容は一切変えない」を、**同じシードと同じ手順なら、セーブの中身 (状態の要約) が 1 ビットも変わらない**こととして守った。
- 足し算と掛け算の順は変えない (浮動小数の丸めが変わるため)。乱数の引き方も変えない。
- 調べる関数に、セーブに残る副作用があるものは、前と同じ時に同じだけ呼ぶ。
  - 例: 人間でない国の財政 `aiFiscal` は、初めて見るときにセーブの項目 `aif` に覚え書きを作る。
- 速さのために足した覚え書きは、セーブに入れない。
  - `_peaceIx`・`_sellMask`。セーブは `SAVE_FIELDS` の一覧だけを書く。

## 2. 何が重かったか (測り方)

- 測ったのはブラウザ (Chromium)。国家選択 8 か国の試合を、画面なしで 0.25 年ずつ進めた。
  - CDP のプロファイルで関数ごと・行ごとの時間を見た。
  - 画面なしの道具 (`tools/headless.js`) は Node の vm で動かすぶん、グローバルの名前を引くたびに代わりの物 (Proxy) を通る。そのため、ブラウザより 2〜3 倍遅く、重い所の割合も違う。
- 8 か国では、1 年に `realmOf` が 17 万回、`yieldOf` が 2.4 万回 (入植地 1 つ・1 刻みに 74 回) 呼ばれていた。
  - 小さな関数を、同じ答えのまま何度も呼び直す所が多い。
  - 重さは 1 か所でなく、何百もの関数に薄く広がっていた。
- 重かった所 (直す前。8 か国・2350〜2380 年):

| 所 | 計算のうちの割合 | 元 |
|---|---|---|
| 交易 (`trade` の売り手の候補探し) | 22〜41% | 買い手 × 足りない資源 × 売り手の 3 重の繰り返し (後半は 1 刻み 1.3 万回)。毎回、国・財政・禁輸・見えている記録を求め直していた。記録は頭から順に探していた |
| 産出と稼ぎ (`yieldOf`・`wagesOf`) | 約 13% | 部門ごと・資源ごとに、技術・働き手・学歴・国有・特性を求め直す。同じ刻みで同じ入植地の稼ぎを 3〜7 回 |
| 学歴 (`eduStep` の `learnAges`・`schoolAges`) | 約 6% | 人のいない年齢の区分のためだけの形 (所得の曲線) を、いつも求めていた |
| 地図の国境の層 | 描くうちの約 60% | 升目の角ごとに、まわりの箱を 9 回引く。升目ごとに配列や Set を作る |

## 3. 直したこと (どれも筋は同じ)

| 所 | 直し | 筋が同じ理由 |
|---|---|---|
| `econSeen` (`economy/econ-intel.js`) | 二分探索にした (前は頭から順に) | 記録は 1 年に 1 つ、古いものから足し、古いものから捨てる。年の順なので、同じ記録を返す |
| `known` (`core/knowledge.js`。観戦でない試合) | 二分探索にした (前は全部を順に) | 記録 (`recordSnapshots`) も年の順。同じ記録を返す |
| `lastPeace` (`ship/war-peace.js`) | 鍵ごとの索引を使い回す (一覧と長さが同じあいだ) | 講和の一覧は、足すか丸ごと置き換えるかでしか変わらない |
| `trade` の売り手の候補 (`economy/trade.js` の `tradeCands`) | 売り手ごとの調べを、買い手のあいだ 1 度だけにした | 交戦・同じ国か・禁輸・見えている記録は、資源によらない。交戦と関税は、売り手の国ごとに 1 度 |
| 同 | 売れる見込みのない売り手を飛ばす | 記録のどれでも余りが 0.5 以下の売り手は、候補にならない。財政を見る調べは前と同じく 1 度はする |
| 同 | 見えている余りが足りないとき、約束した量を引く前に飛ばす | 約束した量は 0 以上 |
| `yieldSet` (`economy/market-economy.js`) | 全部門の産出を 1 度に求める | 掛け算の順は `yieldOf` と同じ。`wagesOf`・`potentialUSD`・経済の 1 と 2 (生産の計画と生産) で使う。1 と 2 のあいだは産出を決めるものが変わらないので、使い回す |
| `incomeFrom` | 求めた稼ぎから所得を出す | 同じ刻みで同じ稼ぎを 2 度求めていた所 (研究・経済の 3 の所得とサービス) で使い回す |
| `eduAvg`・`eduStep` (`economy/demography.js`) | 所得の形の学力と区分ごとの平均は、要るときだけ求める | 区分の人数は、その区分を見るまで変わらない。要るかを先に調べられる |
| `govsYearly` (`economy/development.js`) の交易路の相手探し | 取引できるかを、相手の国ごとに 1 度 | `tradeBlocked` は相手の国だけで決まる |
| `procureFrom` (`economy/colonize.js`) | 交戦・禁輸の調べを、相手の国ごと・星系ごとに 1 度 | 取り寄せ元を選ぶあいだ、国・財政・交戦の知らせは変わらない |
| 地図の国境の層 (`screen/galaxy-view.js`) | まわり 3×3 の箱の一覧を、箱の列ごとに 1 度つなぐ。升目ごとの配列と Set をやめる。同じ国の候補は 1 度だけ比べる | 比べる順・式・道を足す順は前と同じ。絵は画素まで同じ |

試して入れなかったもの:
- `econSeen` の結果を、組ごとに刻みをまたいで覚える形。速さは変わらなかった (二分探索が十分に速い)。
- 売り手の候補探しを小さな関数に分けたのは入れた (`tradeCands`)。ただし、それだけでは速さはほとんど変わらなかった。

## 4. 筋が同じことの確かめ

- **状態の要約** (`tools/headless.js` の hash。セーブの中身の FNV-1a)。main と直したあとで、15 試合 × 150 年を 10 年ごとに比べ、すべて同じだった。
  - 観戦の試合 11: 8 か国 (実在の銀河 1・2・3・4・6、自動生成の銀河 5)、6 か国 (実在 1・2、自動生成 7)、地球だけ (実在 3・4)。
  - 観戦でない試合 4: 人間の席は何もしない。8 か国 (実在 2・3、自動生成 8)、6 か国 (実在 4)。
- **ブラウザでも同じ**: 上の測りの終わりの要約が、main と同じ。
- **国境の層の絵**: main と直したあとで、同じ状態・同じ視点 (ズーム 6 段) から描いた層の画素が、3 試合ですべて同じ。
- **試験**: 手元で `tools/tests` を CI と同じ判定で回して合格 (シミュレーション版の `simvassal` は CI で)。
- **CI**: 自動対戦の「試合の筋が main と同じだった銀河」が 8 / 8 になる。

## 5. 測り (ブラウザ。この作業場所の Chromium。8 か国)

計算だけ (`tools/perf-bench.js`。1 年あたり):

| 銀河 | 期間 | main | 直したあと | 倍 |
|---|---|---|---|---|
| 2 | 2350〜2380 年 | 77.8 ms | 66.6 ms | 1.17 |
| 3 | 2350〜2380 年 | 110.9 ms | 62.7 ms | 1.77 |
| 3 | 2420〜2440 年 | 243.1 ms | 117.8 ms | 2.06 |
| 2 | 2420〜2440 年 | 293.3 ms | 147.3 ms | 1.99 |

画面も描く実際の動き (銀河 3・2420 年から 20 秒):

| 速さ | 進んだ年 (main → 直したあと) | 1 秒あたりのコマ | 1 コマの時間 (中央値) |
|---|---|---|---|
| 4 年/秒 | 42 → 64 年 (1.5 倍) | 5.5 → 9.9 (1.8 倍) | 167 → 83 ms |
| 16 年/秒 | 50 → 101 年 (2.0 倍) | 1.7 → 3.5 (2.0 倍) | 633 → 283 ms |

- 国が増え、入植地が増える後半ほど、効きが大きい (交易の 2 乗で重くなる所を直したため)。
- 測りの揺れは ±10〜15% ほど。この作業場所は画面を CPU で描くので、絵を貼る時間 (drawImage) が実機より重く出る。

## 6. 10 倍に届かない理由と、次の手

- 筋を変えずにできるのは、同じ答えを何度も求め直す所を減らすことだけ。
  - 重さは何百もの関数に薄く広がっている。直したあとも、交易・予算・人口・研究・年ごとの AI の判断・記録が、それぞれ数 % ずつ残る。
  - この形では、3 倍ほどが上限と見る。
- **大きく軽くできる見込みのある所 (筋が変わるので、決めてもらう。QD-118)**:
  - ブラウザでは、1 コマごとに「経過時間 × 速さ」(0.25 年まで) だけ進め、その度に経済を 1 回まるごと回している。
    - たとえば 1 年/秒・60 コマ/秒では、1 年に 60 回。画面なしの道具と CI は 0.25 年ずつ (1 年に 4 回)。
    - コマの速さで刻みが変わるので、いまも端末によって数字が少し違う。
  - 経済を 0.25 年ごと (固定の刻み) にまとめて回せば、ふつうの速さでは計算が数分の一になる。
    - ただし、刻みが変わるぶん数字は少し変わる。地図の動きを滑らかに保つ作りも要る。
- そのほかの手:
  - 速く進めているあいだは、国境の層の描き直しを 0.5 秒に 1 度にする (見た目の更新が少し遅れる)。
  - 計算を画面と別の流れ (Web Worker) に移す。大きな作り直しになる。

## 7. 道具

- `tools/perf-bench.js`: ブラウザで、1 年あたりの計算の時間と状態の要約を出す。
  - main と比べるときは、`node tools/src.js --ref origin/main --out main.html` で main を組み立てて渡す。
  - 速さを直す PR では、要約が main と同じことと、時間を並べる。
