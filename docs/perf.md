# 処理の速さ (2026-10-26)

ユーザーの依頼「ゲームの処理速度を 10 倍にして。ゲームの内容は一切変えないで」に対してしたことと、測った結果です。**試合の筋は 1 ビットも変えていない** (同じシード・同じ手順なら、どの節目の状態の要約 (hash) も前と同じ)。

## 1. 結果

作業は 2 回に分けた (1 回目は 2.1〜2.5、2 回目は 2.6〜2.8)。下の数は、同じ機械で 3 つの版を続けて測ったもの (2 回目のあとに測り直したので、1 回目のときに書いた数とは少し違う)。

| 測ったもの | 元の版 | 1 回目の後 | 2 回目の後 | 比 (元 → 2 回目の後) |
|---|---|---|---|---|
| ブラウザ (Chromium) で試合を 300 年進める時間 (6 か国・シード 1・2・3 の合計) | 41.4 秒 | 23.5 秒 | 20.4 秒 | **×2.03** |
| 実際の画面で最高速 (年 64 年) にしたときの 1 秒あたりの年数 (2550 年ごろ) | 11.2 年 | 17.2 年 | 18.6 年 | ×1.66 |
| 同じく 2350 年ごろ | 14.8 年 | 22.3 年 | 24.4 年 | ×1.65 |
| 画面なしの版 (`tools/headless.js`。CI の自動対戦・測る道具) で 300 年 (シード 1) | 52.9 秒 | 約 12 秒 | 8.1 秒 | **×6.5** |
| 星間マップの国境の層を描き直す時間 (実際の画面の 1 コマに占める割合) | 15% | 10% | 10% | — |

- 試合の筋が同じことは、10 の筋 (国家選択あり・なし、観戦・観戦なし、シミュレーション版、途中で保存して読み込み直して続ける筋を含む。150〜300 年) と、長い 4 本 (400〜500 年) の節目ごとの状態の要約で確かめた。2 回目からはセーブの JSON の鍵の並びが変わったので、鍵を並べ替えてから作った要約で比べている (2.9)。ブラウザでも 300 年後の要約が元の版と同じ。
- 前の版 (高付加価値物品のない、src を分ける前の基準の main `3a5b5d9`) で作ったセーブを読んで 30〜40 年続けた筋も、元の版と同じ。
- 同じ版の中で、保存→読み込み→保存が 1 文字も同じで、読み込んだ試合と続けて回した試合が 1 文字も同じセーブに進む (5 つの筋)。
- 国境の層は、前と同じ絵になることを、同じ試合・同じ視点の canvas の画素で確かめた (1 回目)。
- `node tools/ci-tests.js` はすべて合格。

**10 倍には届いていない** (ブラウザで約 2 倍。実際の画面は描画の時間も入るので約 1.7 倍)。理由と、さらに速くする道は 3。

## 2. したこと

### 2.1 いちばん効いたもの: 物の形を固定する (JavaScript の JIT のため)

ブラウザの JavaScript (V8 など) は、物の「形」(値の名前と並び) ごとに速いコードを作る。試合 (Game) の物は、作ったあとから覚えておく表などの値が 20 ほど足され、そのたびに形が変わっていた。形が何度も変わるのを見た所 (`this.fertility(…)` のようなメソッドの呼び出しや `this.galaxy` の読み出し) は、遅い道 (megamorphic) に落ちて戻らず、メソッドの埋め込みもできなくなる。

途中で書き込む値を `GAME_LATE_FIELDS` (core/game-consts.js) にまとめ、constructor の始めに undefined で置くだけで、試合を回す時間が約 2 割減った。セーブは決まった項目だけを書くので、セーブの中身は変わらない。`tools/tests/shape.js` が足し忘れを見つける。

### 2.2 同じ値の計算し直しをやめる・使わない値を計算しない

| 所 | 前 | 後 |
|---|---|---|
| `yieldOf` (1 人あたりの産出) | 1 刻みに約 5000 回、毎回 国・技術・種族の倍率・統治体制・天体を引き直す | `yieldCtx` で入植地ごとに 1 回だけ引き、7 つの部門に使う |
| `wagesOf` | 同じ状態で 2 回 (研究と消費の所) | 1 回 (`incomeWith`) |
| `servShare(所得)` (exp と log) | 同じ所得で 1 刻みに 4〜5 回 | 入植地ごとに前の答えを覚える |
| `eduStep` | 人のいない区分のための平均 (20 区分ぶんの exp・log) を毎回全部 | その区分が要るときだけ |
| 採掘基地の産出 | 計画と生産で 2 回 | 1 回 |
| 交易の候補探し | 資源ごとに、売り手の記録・運ぶ年数の利子を引き直す | 売り手ごとに 1 回 (関税は元と同じ時点で初めて引く。AI の国の財政はセーブに入るため) |
| 荷の区間 (`rebuildTransit`) | 荷と資源ごとに | 同じ道のりの荷で使い回す |
| 遮蔽の黄金分割の探索 (`shieldOf`) | 入植船の費用を引くたびに 42 回 | 同じ引数なら答えを覚えて写しを返す |
| 中央銀行の国ごとの星系 | 国ごとに全部の星系を調べる (2 回) | 1 回で分ける (`systemsByRealm`) |

### 2.3 探し方と毎回の生成を変える

- 年の順に並んだ記録から「t 以前でいちばん新しいもの」を頭から探していた所 (`econSeen`・`cbRateAt`・`seenBy`) を二分探索に (同じ結果)。
- `realmOf` (1 刻みに 1.5 万回) は、ふつうの連鎖を `Set` を作らずにたどる (輪になった連鎖のときだけ前の数え方)。
- 毎刻みの一覧の掃除は、消えるものがなければ配列を作り直さない (`keepWhere`)。作り直すと、続く `keepGhosts` が全件で `Set` を作っていた。
- `routeBetween`・`reach` の印の文字列、`warKey` の文字列、`sysDist` の WeakMap、`lastPeace` の全件の探索、`fertility` の表を毎回作る所をなくした。
- 決まった計算 (DMath) の 2^k と 1/(2n+1) を始めに表にした (1040 万回の比べで、どの値も 1 ビットも同じ)。
- `economy` を、同じ順の `econ…` のメソッドに分けた (大きすぎて JIT の最適化に時間がかかり、外れやすかった)。

### 2.4 画面

- 国境の層: 升目の角ごとに近くの入植星系を探すとき、箱ごとに 1 回だけ並べる。升目ごとの配列・`Set`・`map` を作らない (描く順と値は前と同じ)。

### 2.5 画面なしの版 (`tools/headless.js`)

前は、グローバルの名前 (`Math`・`Set`・`Infinity` やゲームの関数) を引くたびに Proxy を通り、試合を回す時間の 6 割ほどがそれだった。ふつうのグローバルを持つ文脈 (`vm.constants.DONT_CONTEXTIFY`。Node 22.8 から) で動かし、知らない名前 (document など) だけをグローバルの prototype に置いた Proxy で受ける形にした。CI の自動対戦と測る道具が速くなる (古い Node では前の形で動く)。

### 2.6 星系の政府の物の形をそろえる (2 回目)

政府 (`govs`) の物は、値の付く順が政府ごとに違って形が 1 つずつ違い (5 つの試合で 885 通り)、値を `delete` していたので 41 のうち 33 が遅い辞書の形だった。値の名前と並びを `GOV_FIELDS` (core/game-consts.js) にまとめ、政府はいつも `newGov` でこの並びの物として作る (読み込みのときも入れ直す)。値を消す所 (36 か所) は `delete` をやめて `undefined` を入れる。どの政府も 1 つの形になった。

`delete` と `undefined` の違い (`'x' in gv`・`Object.keys(gv)` など) を見ている所はなく、すべての `delete` を `undefined` にしても試合の筋は同じだった。

### 2.7 資源ごとの量と収支の表を、番号の並びにする (2 回目)

星系の在庫・市場 (ふだんの消費・値段・ならした値段)・生産と消費・稼働率・受注残・運ぶ途中の荷などの、資源ごとの量は、名前の物 (`{ food, water, … }`) だった。資源を回す所 (`for (const r of RES) st[r]`) は、名前を変えながら同じ所で引くので、V8 の遅い道 (megamorphic な読み書き) になる。

- 資源ごとの量を、`RES` の順の並び (`ResVec`。core/world.js の `namedVec`) にした。名前でも引ける (`st.metal` と `st[RI.metal]` は同じ。名前で引く所はそのまま動く)。
- 重い所 (市場の値段・生産・工業・消費・交易・荷の区間・捨てる分・経済の記録) は番号で回す。資源ごとの表は番号の版 (`PRICE_I`・`COVER_I`・`ELASTIC_I`・`RES_KG_I`・`basePriceI`) を使う。`mv`・`price` は名前でも番号でも受ける。
- 政府の収支の表 (`gv.ledger`・`gv.eledger`。年あたりにならした値) も、`LEDGER_LABEL`・`E_LABEL` の順の並び (`LedgerVec`・`ELedgerVec`) にした。この刻みの分 (`gv.led`・`gv.eled`) は、種類が決まっていない (研究開発の税額控除など、表にない種類も記帳する) ので名前の物のまま。
- セーブには前と同じ名前の物で書く (`toJSON`・`plain`)。読み込みでは並びに入れ直す (`resFrom`)。前の版のセーブに値のない資源・種類は、並びの中で `undefined` のまま持つので、前の版のセーブを読んだあとの筋も前と同じ (高付加価値物品のない版 (src を分ける前の基準の main `3a5b5d9`。`tools/tests/save.js` が読むもの) のセーブで確かめた)。
- 画面と記録 (星系の様子の記録 `snapshot`) には名前の物の写しを渡す。

型付き配列 (`Float64Array`) は `undefined` を持てない (前の版のセーブの「値がない」を表せない) ので、ふつうの配列 (`Array` を元にした型) にした。番号で引く速さは、小さな試験で型付き配列の 8 割ほど (名前で引くより 5〜7 倍速い)。

### 2.8 入植地の物の形をそろえる (2 回目)

2.7 のあと、残った遅い道の多くは入植地 (`colonies`) の値の読み出し (`c.pop`・`c.sys`・`c.sh` など) だった。入植地も、値の付く順で形が分かれていた (4 つの試合で 12 通り)。政府と同じく、値の名前と並びを `COL_FIELDS` にまとめ、`newCol` で作る (読み込みのときも入れ直す)。`tools/tests/shape.js` が、政府と入植地に一覧にない値が付いていないかを見る。

### 2.9 セーブの中身と JSON の鍵の並び

2.6〜2.8 で、セーブの JSON の**鍵の並び**が変わった (政府と入植地は `GOV_FIELDS`・`COL_FIELDS` の順、エネルギーの収支の表は `E_LABEL` の順)。**中身 (値) は同じ**で、鍵を並べ替えてから作った要約は前の版と同じ。同じ版の中では、同じ状態から同じ並びの JSON になる (保存→読み込み→保存が 1 文字も同じで、読み込んだ試合と続けて回した試合が 1 文字も同じセーブに進む。ネット対戦の状態の要約が合う)。前の版と比べるときは `node tools/bench.js --canon`。

## 3. 10 倍に届かない理由と、さらに速くする道

いまの時間は、特定の重い所がなく、ほぼ平らに散らばっている (いちばん重い関数でも全体の 3.4%)。2 回目 (2.6〜2.8) で、V8 の記録 (`node --prof`) の「形がばらばらな物の値の読み書き」(megamorphic な読み書き) は、全体の約 2 割から約 1 割に減った。残りは、部門 (`farm`・`mine` …) ・関税や帳簿の種類・お金の帳簿 (`hh`・`fm`) を名前で引く所に少しずつ散らばっていて、1 か所あたり全体の 0.5〜1% ほど。

| 道 | 見込み | 変わること |
|---|---|---|
| 政府の物の形をそろえる | (2.6 でした。前に見込んだ 1 割には届かず、約 3%) | セーブの JSON の鍵の並び (中身は同じ) |
| 資源・帳簿を番号の並びにする | (2.7 でした。前に見込んだ 2〜3 割には届かず、画面なしの版で約 8%) | 同上 |
| 入植地の物の形をそろえる | (2.8 でした。画面なしの版で約 9%) | 同上 |
| 部門 (就業の割合・稼ぎ) やお金の帳簿の欄も番号の並びにする | 1 か所あたり 0.5〜1% | 経済のコードと、セーブの読み書き (変換を挟む) |
| 試合の計算を Web Worker (別の CPU) に移す | 実際の画面で 1〜2 割 (描画と並べて動く) | 画面が試合の物をじかに読んでいる所を、写しを読む形に作り替える |
| 刻み (0.25 年) を粗くする・年 1 回の処理を間引く | 数倍 | **試合の筋が変わる** (今回の「内容を変えない」に反する) |

## 4. 測り方 (同じことをもう一度するとき)

- `node tools/bench.js` — いまの src と origin/main を同じシードで回し、時間と、節目ごとの hash が同じかを並べる (`--seeds`・`--years`・`--nations`・`--reps`)。セーブの JSON の鍵の並びが違う版と比べるときは `--canon` (2.9)。
- `node tools/tests/shape.js` — 試合の物に、作ったあとから値が足されていないか。政府・入植地に `GOV_FIELDS`・`COL_FIELDS` にない値が付いていないか。
- プロファイル: `node --cpu-prof tools/bench.js …` (関数ごと) や `node --prof` → `node --prof-process` (megamorphic な読み書きなど V8 の内側の時間)。ブラウザでは Playwright の CDP (`Profiler.start`) で取れる。
- 遅くしないための決まりは `docs/content.md` の 4。
