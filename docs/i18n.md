# 画面の文字列と翻訳 (回 T1・B-073・B-075)

回 T1 (2026-10-29) で、画面の文字列を訳せる形にし、英語を入れた。中国語 (B-076) は訳し方 (QD-17) が決まってから、同じ形で足す。用語は `docs/glossary/` (用語集) にそろえる。

## 1. 考え方

- **正本はコードの中の日本語の文**。文字列を別のファイルの番号 (`msg_123`) に置き換えるのでなく、日本語の文そのものを鍵にする (gettext と同じ形)。コードを読む人にも、ほかのレーンにも、いままでどおり日本語で読める。
- **言語ごとの表** (`src/outward/lang-en.js` の `I18N_EN`) が、日本語の文 → 訳。1 か所に集めるのは道具 (`node tools/i18n.js`) の仕事で、コードの中の日本語をすべて (ほかのレーンの表の値も) 集めて、表の鍵とそろえる。
- **試合の状態は言語によらない**。出来事・記録・名前・指令の文は、どの言語でも日本語のまま状態に入る (セーブと状態の要約が言語で変わらない。だから、言語の違う端末どうしのネット対戦でも要約はずれないはず。確かめたのは画面なしの版の観戦の筋だけで、言語の違う 2 台のネット対戦はまだ試していない)。英語の画面は、出すときに訳す。
- **日本語のときは何も変わらない**。翻訳の関数は渡した文をそのまま返し、画面の文字も試合の筋も、入れる前と 1 字も違わない (状態の要約が main と同じ: `tools/tests/i18n.js` と CI の自動対戦の表)。

## 2. 3 つの関数 (`src/outward/i18n.js`)

| 関数 | 使う所 | 何をするか |
|---|---|---|
| ``TR`…${x}…` `` / `TR('…')` | 画面に出すだけの文 (画面の部品のファイル: `screen/`・`*-ui.js`・`politics/panels.js`・`outward/` など) | いまの言語の訳を返す。訳がなければ日本語のまま。差し込む値に日本語があれば `TX` で訳す (ただし `value="…"`・`data-…="…"` などの属性に入れる値は訳さない。選んだ値が指令や名前として試合に入るため) |
| ``JA`…${x}…` `` | 試合の状態に入る文 (出来事・記録・決めること・名前。試合の中身のファイル) | どの言語でも日本語のまま返す。英語の画面のときは、作った鍵と値を覚えておき、出すときに `TX` がそのまま訳す |
| `TX(s)` | 状態から来た日本語の文を画面に出す所 | 表 → 数の書き方 → 名前 → `JA` で覚えた文 → 文の型 (`{0}` を含む鍵) → 名前と記号の組み立て → 区切りで分ける・表の言葉を文の中で探す、の順に訳す。訳せない所は日本語のまま |

- テンプレートの `${…}` は、表の鍵では `{0}`・`{1}`… になる (`TR`年前 ${n} 年`` → 鍵 `年前 {0} 年`)。訳では順番を入れ替えてよい。月の番号は `{1:month}` と書くと月の名前 (Jan…Dec) になる。
- ふつうの文字列 (`'食料'`) は、そのまま鍵になる。表の値 (`RES_LABEL` など) は変えずに置き、画面に出すときに `TR` の値として、または安全網 (下) で訳す。
- **安全網**: 英語のときは、画面に入った文字 (文字の部品と `title`・`placeholder`・`aria-label`・`alt`) と地図に描く文字 (`canvas` の `fillText`) のうち、日本語のまま残ったものを、入ったときに `TX` で訳す (`MutationObserver`)。`TR` の外で表の値を差し込んだ所も、これで訳せる。訳さないもの (言語の名前「日本語」) は `translate="no"` の中に置く。
- 名前: 作った星系の名前は、作るときに英字の形を覚える (`nameAlias`。用語集の `names.systems`)。種族 (「カラ人」→ `Kara`)・国 (語幹 + 接尾辞。表の最後の区切りの `{stem}王国` などの型)・実在の星 (表) も訳す。カタカナだけの見知らぬ名前 (自作の種族など) はローマ字にする。
- 数: 人口の書き方 (`fmtPop`) は試合の記録の文 (時代の課題など) にも入るので、日本語のまま作る (`JA`)。英語の画面では、出すときに `TX` が「120億人」を `12B`、記録の「3 万人」を `30k people` にする。日付と時刻は `LOCALE` (`ja-JP`・`en-US`)。
- **画面の部品のファイルの関数を、試合の中身から呼ぶとき**は、その関数の文を `TR` でなく `JA` にする (回 T1 で `fmtPop` が `TR` のままで、英語の時代の課題に英語が入った。`tools/tests/i18n.js` が見つけた)。

## 3. 言語の選び方と切り替え

- 選ぶ順: URL の `?lang=en` → 前に選んだ言語 (`localStorage` の `nlu-lang`) → ブラウザの言語 (日本語なら日本語、ほかは英語)。自動の試験 (`navigator.webdriver`) と画面なしの版 (`tools/headless.js`) は、決めなければ日本語。
- 切り替え: ホーム画面の下の「日本語 / English」と、メニュー (≡) の「🌐 English」。いまの試合をセーブして読み込み直す (表を読み込みのときに引く所があるため)。
- 画面なしの版で言語を決める: `require('./tools/headless').load({ lang: 'en' })`。

## 4. 画面に文字を足すとき (どのレーンも)

1. 画面に出すだけの文は `TR` で包む (``TR`…${x}…` `` か `TR('…')`)。試合の状態に入る文 (`event`・`message`・`councilAdd`・決めることの文・名前) は `JA` で包む (ふつうの文字列ならそのままでよい)。比べるための文字列 (`=== '市民'`・`startsWith('[自動]')`) は包まない。
2. `node tools/i18n.js --sync` で表に鍵を足す (訳のない鍵は `null` で入る。コードから消えた鍵は消える)。
3. `src/outward/lang-en.js` の `null` を英語にする。用語は `docs/glossary/terms.json` の訳にそろえ、文の調子は「古い報告書」(簡潔に)。`{0}` と HTML の札は鍵と同じに保つ。
4. `node tools/i18n.js` (または `node tools/ci-tests.js i18n`) が「翻訳の表 合格」になることを確かめる。**CI の試験 `i18n` は、訳のない鍵・表にない鍵・`{0}` や HTML の札の食い違いがあると落ちる**。
5. 英語の画面で日本語が残っていないかは `node tools/i18n-scan.js [年数]` (ホーム・国家選択・地図とタブ・帝国の欄・出来事・星系の欄を開いて、残った日本語を数える。画面の写しは撮らない)。

- 日本語の文を少し直すと鍵が変わり、英語は「訳のない鍵」に戻る (CI が落ちる)。直した文に合わせて英語も直す。
- 表のファイルは 1 行に 1 つで、区切り「// == ファイル」は、その鍵が最初に出てくるファイル。ほかのレーンと同じ時期に表を直すと、区切りの中の行がぶつかることがある。そのときは両方を残してから `--sync` で並べ直す。

## 6. 回 T1 でしたこと・測ったこと

- 書き換え: 画面の部品のファイル 65 個で、日本語の文字列とテンプレートを `TR`・`JA` で包んだ (一度きりの台本。比べる所・状態に入る所・表の値は包んでいない)。日本語の画面と試合の筋は変わらない (状態の要約が書き換えの前と同じ。CI の全試験が合格)。
- 表: 鍵 2,302 (画面の骨組み 84・試合の中身と表の値・画面の部品)。英語はすべて Claude の訳で、用語集にそろえた。名前の作り方の型 27。
- 英語の画面に残った日本語 (`i18n-scan.js 200`): 0 種類 (書き換えの直後は 1,120 種類)。
- 試合の状態が言語によらないこと: 6 か国 × 300 年 × 5 つの銀河で、日本語と英語のセーブの中身が 1 か所も違わない (CI の試験より長い確かめ。一度きり)。
- 重さ: 英語の画面の描き直しの速さは日本語とほぼ同じ (最高速の 8 秒で、日本語 41〜47 コマ/秒・英語 40 コマ/秒。表の引き直しは覚えておく)。組み立てた `index.html` は 318 KB → 377 KB (英語の表のぶん)。
