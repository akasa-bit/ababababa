# 引き継ぎメモ

新しいセッションで作業を続けるためのメモです。**作業は、Project を使わずにセッションをつないで続ける** (手順といつもの約束は `docs/session-start.md`、各回の最初のメッセージは `docs/sessions.md`)。まずこのページと `README.md`・`docs/design-pillars.md`・`docs/reality-check.md` を読んでください。

**ユーザーがこれまでに送った依頼は、すべて `docs/requests-log.md` にそのまま残してあります。** 新しいセッションは前の会話を読めません。画面や遊びの細かい決まりの多くはそこにしかないので、仕組みを変える前に、関係する依頼を探してください。変更の理由は `git log` (PR の本文) にもあります。

## 1. いつもの約束 (ユーザーとの決まり)

- 報告は日本語で書く (考えるときの言葉は何でもよい、とユーザーが言った)。
- 変更ごとに、コミット → プッシュ → PR → スカッシュマージまで行う。**マージはユーザーの許可を待たずに毎回行う** (2026-10-20 の指示。requests-log の 137)。CI のコメントの表がすべて合格なのは見る。PR の本文にテンプレートはない。
- 機能を壊さない (下の「試験」をすべて通してからマージする)。
- 画面は Xiaomi Pad 8 Pro (3200×2136・144Hz、CSS で横 1280×780・縦 854×1200、画素の比 2.5) で確かめる。Playwright の viewport をこの大きさにして撮る。新しいゲームで出る「遊び方の記録にご協力ください」(プレイ記録の同意) は、撮るときは「記録しない」(`#endbox [data-consent="no"]`) を押して奥へ進んでよい (2026-10-25 のユーザーの指示。`docs/requests/2026-10-25-GA.md` の GA-3)。
- 「スキン 6」= グラファイト (黒に近い灰色)・白・NASA の赤橙の配色。配色の 10 案から選ばれた唯一の配色で、切り替えは削除した (下の 15)。
- 作業ブランチは、そのセッションで指定されたもの (例: `ccr-f641c31e-9hmryq`)。マージのあとは `git fetch origin main && git checkout -B <ブランチ> origin/main` で main に合わせ直し、`--force-with-lease` でプッシュする。 強制プッシュをしないときは、合わせ直したあと `git merge -s ours origin/<ブランチ>` で前の PR のブランチを取り込んでから、ふつうにプッシュする (中身は main と同じなので、ぶつからない。W2。`docs/parallel.md` の 4)。
- リポジトリに入れるもの (コミット・PR・コード・文書) に、AI のモデルの名前を書かない。
- コミットの末尾の行と PR の本文の末尾は、そのセッションで与えられる案内 (共同作者の行・セッションへのリンク・「Generated with Claude Code」の行) に従う。
- 試験で書き出す画面の写し (`shots/`) と、作業用の台本は、リポジトリの外 (作業用のフォルダ) に置く。リポジトリに残すものは `tools/` に入れる。

## 6. 作業のこつと落とし穴

- **画面の描き直しと入力欄**: `Cloud.run` などは、始めに「…」を出すために画面を描き直す。入力欄の値は、描き直す前に読んでおく (前に、部屋のコードとメールのログインで値が消えた)。
- **試験は実時間に左右されないように**: ページを開くと、ゲームは画面の更新ごとに実時間で進む。試合の中身を確かめる試験は、`requestAnimationFrame` を止めるか、`newGame(シード)` で作り直してから `advance` で進める (前に `regime.js` が、CI の機械の速さで家臣の数が変わって落ちた)
- **試験の家臣の選び方**: 星系の数や試合の筋が変わると、`regime.js` のように「家臣を 3 つ選ぶ」試験が外れる。指令は地球に届いている記録 (`known`) で判断されるので、試験でも `g.known(id)?.lord` を見る。
- **銀河の版**: 星の表を変えずに使う星を変えるときは、`GALAXY_GEN` を上げて、古い版のセーブは古い作り方のまま読む (版 3 = `THIN_SLAB` の板)。星系の番号は並びの位置 (`systems[id]`) なので、間を飛ばさない。

- `src/` を直したら、手元で試すときは `node tools/build.mjs` でゲーム版を作り直す (試験は公開用の HTML を開いて動かす)。組み立てた `index.html` はコミットしない (回 R3。`docs/src-files.md` の 3)。
- **決まった計算**: 試合と銀河の計算に `Math.pow`・`**`・`Math.exp/log/sin/cos/cbrt/atanh/hypot/log10` を書かない。`GM.pow(…)` などを使う (`DMath`。ブラウザの版で末尾の桁が変わらない)。画面の描画は `Math` でよい。守らないと `tools/tests/headless.js` が落ち、ネット対戦が端末の間でずれる
- **CI**: PR を作ると GitHub Actions (`.github/workflows/ci.yml`) が試験と自動対戦を回し、表を PR のコメントに書く。マージの前にコメントの表がすべて合格か見る。手元では `node tools/ci-tests.js`
- **画面なしの版**: `tools/headless.js` (Node で試合を回す。ボット・CI・つり合いの点検の土台)
- **決定性**: 試合の乱数は `Game.rand` (状態 `rs` はセーブに入る) だけを使う。`Math.random` は見た目にだけ使う。新しい乱数を増やすと試合の筋は変わるが、決定性の試験は通る。
- **セーブの互換**: 銀河は読み込みのたびにシードから作り直す。銀河の作り方を変えるときは、版の番号 (`GALAXY_GEN`) を上げ、古いセーブは古い作り方で読む (例: η⊕ の版 2)。
- **備蓄の出入り**はすべて `mv(星系, 資源, 量, 種類)` を通す (直接 `stockOf(...)[r] +=` と書かない。書くと `conserve.js` が落ちる)。新しい種類を足すときは、試験の IN・OUT の一覧にも足す。
- **エネルギーの出入り**は `bookE`、船の推進は `bookShip` を通す。
- **状態を変える操作**はすべて `issue(命令, 内容)` を通す (ネット対戦とホットシートのため)。艦隊への指令など政治力の要らない命令は `PC_FREE_ACTS`。
- **画面に出す値**は、光の遅れのぶん古い記録 (`known`) から作る。新しい値を出すときは、スナップショット (`known` を作る所) にも足す。
- **版ごとに違う値**は `EDITIONS` にだけ置く。版を分ける理由は `docs/reality-check.md` に書く。
- 自動対戦は CPU を食う (4 並列で 30 の銀河 × 300 年 × 2 つの版で約 15 分)。`run_in_background` で回し、待つ。
- `pkill -f` に、自分のコマンド行にも含まれる文字を使わない (自分のシェルが止まる)。

## 11. セーブとネット対戦の決まり

- **セーブ**: `buildSave` が書く `v: 2` の形。実在の銀河なら `galaxy: 'real'`、銀河の版 2 以上なら `gen` を入れる。読み込みでは、シードから銀河を作り直してから `restore` する。
- **保存の名前**: ゲーム版は前の名前のまま `moribin` (IndexedDB の名前・`moribin-save-v1` など)。Moribin のころのセーブをそのまま読むため。シミュレーション版は `nlu-sim`。
- **新しい状態を足すとき**
  - かならずセーブに入れる。入れないと、読み込んだあとに結果がずれ、決定性の試験とネット対戦の要約が合わなくなる (前に `ghosts.fleets` で起きた)。
  - プレイヤーごとに違う値は `PLAYER_KEYS` に入れる。ネット対戦の要約 (`Net.hash`) は `pi`・`savedAt`・`endShown`・`spectate`・`credits`・`PLAYER_KEYS` を除いて計算する。
  - 年 1 回の処理は、どの端末でも 1 人目のプレイヤーの立場で進む。「いま操作しているプレイヤー」によって結果が変わる処理を入れない。
- **AI の国も席を持つ** (2026-10-28 のユーザーの依頼「AI 国家にも、恐怖度や政治力などの、人間国家が持つすべての機能を」。回 SE5。`docs/requests/2026-10-28-SE.md` の SE-1)。
  - 国家選択の国は、どれも `players` に席 (政治力・議会・国家方針・決めること・時代の課題・威圧の設定など `PLAYER_KEYS` の値) を持つ。人が動かす席は `human: true`、AI が動かす席は `human: false, ai: true` (`addAiSeats`。前のセーブは読み込みで足す)。
  - `isHuman(cap)` = 人が動かす国、`isSeat(cap)` = 席を持つ国 (人の国と AI の国)、`playerOf(cap)` と `asRealm` はどの席でも引く。`eachPlayer` は人の席だけ、`eachSeat` はすべての席。
  - 人間の国だけにあった仕組みを足すとき・直すときは、「人が動かすから」なのか「席を持つ国の仕組みだから」なのかで `isHuman` と `isSeat` を選ぶ。年ごとの政治 (`politicsYearly`) と威圧・自動防衛は `eachSeat` で回り、AI の席は観戦モードと同じ AI (`earthPoliticsYearly`) が決める。戦争の判断は前のまま `realmsYearly` (AI の国の型)。
  - AI の席の出来事と記録は、その席だけに見せる (`events` と `log` の `p`)。光の遅れの記録 (`snaps`) は、いちばん遠い席の分まで残す。

## 15. 画面の決まり (ユーザーと決めたこと)

- **配色**: スキン 6 だけ。色は意味にだけ使う (自国・敵・警告・良い知らせなど。`:root` の変数)。
- **見た目**: ボタンとタブは額縁のような枠。文字は古い報告書風の書体 (Google Fonts の Courier Prime・Special Elite・Zen Antique・Zen Old Mincho)。ボタンには動かない白い走査線。文字のぶれ (信号の揺れ) は設定の「画面の動き」で切り替える。
- **大きさ**: 文字の大きさは 4 段階、余白は 8px の倍数。ボタンは指で押せる大きさ (44〜48px)。文字のコントラストは基準を満たす。
- **説明文**: 長い説明は画面から外し、「説明」を押したときだけ出す (`helpify` が 50 字以上の説明文を自動で畳む)。
- **知らせ**: 出来事は地図の端の帯に流す。重大なものは消えずに残り、押すと地図がそこへ飛ぶ。イベントタブは履歴を探すときだけ使う。
- **情報の古さ**: 古い情報ほど薄く描き、「○年前の情報」を添える。
- **右の欄**: 星系を選んでいないときは出さず、地図を広げる。
- **押したボタンが指から逃げない**: 押して中身が増えても、押したボタンの位置は動かさない (増えた分は上へ伸ばす。交易路の連打のため)。
- **背景**: 星間マップは天の川の実写 (NASA)、星系マップは太陽系が北アメリカ星雲、ほかの星系はユーザーが選んだ 17 枚 (`assets/systems/`)。抑えめの明るさにする。
- **アイコン**: ユーザーが候補から選んだもの。出典とライセンスは README の「アイコンの出典」。
- **地図の描画**: 動かしているあいだは毎コマ描き、止まっていて何も変わらないときは描き直さない。
- **星間マップ**: 3 次元の地図 (回す・傾ける) のまま。国境だけステラリス風に、国の領土 (入植星系のまわり 5 光年、近いほうの国) を塗り分ける。星の密度を下げるため、銀河の版 3 から銀河面 ±2 光年の板の星だけを使う (ユーザーの指示)。

## 17. S4 の中身: 第一次・第二次・第三次産業と、惑星の経済の発展 (Claude の案。ユーザーの確認待ち)

ユーザーの言葉は「第三次産業と研究を作ってみようか。それでまた考えよう」と「経済: 第三次産業と研究を入れ、そのあと農業の割合を見直す」まで。下の設計は Claude の案で、まだ決まっていない。始める前にユーザーに見せて選んでもらう。

### いまのゲーム

- 産業は 3 つだけ: 農業 (食料)・鉱業 (水・金属・燃料・希少元素)・工業 (工業品)。第三次産業 (サービス) と研究はない。
- 人口の割り振りは、入植地ごとの方針 `FOCUS` で固定 (自給: 農業 50%・鉱業 25%・工業 25%、農業: 80%・10%・10% など)。所得が上がっても割合は変わらない。
- 施設の段階 (`lv.farm`・`lv.mine`・`lv.factory`。0〜10) が上がると、それぞれの生産が 1 段階 25% ずつ増える。
- 「時代」(石器・農耕・産業・情報) は先住民にだけある (`TECH_LABEL`)。入植地の経済の発展段階はない。
- 現実との差: 高所得国の農業の就業者は約 3% だが、ゲームでは 50〜80% (P0 監査の 7)。

### 案: 惑星の経済が発展すると、産業の割合が移っていく (構造転換)

- **発展の度合い** = 1 人あたりの所得 (生産額 ÷ 人口)。施設の段階・交易・研究で上がる。
- **就業の割合は所得から決まる** (Herrendorf・Rogerson・Valentinyi 2014 の構造転換の型)。
  - 第一次 (農業・鉱業): 所得が上がるほど減る (エンゲルの法則と、農業の生産性の伸び)。
  - 第二次 (工業): 途中で増え、高所得で減る「こぶ型」。
  - 第三次 (サービス・研究): 所得が上がるほど増える。
  - 曲線は、GGDC 10 部門データベースと ILOSTAT (世界銀行 SL.AGR.EMPL.ZS など) の生データから推定する (目標 R10: 所得の各分位で、ゲームの割合が実データの四分位範囲に入り、工業の頂点の所得が範囲に入ること)。
- **方針 `FOCUS`** は、割合を固定するものから、曲線のまわりで少し寄せるもの (例: ±10 ポイント) に変える。
- **第三次産業の効き目**: 税収・人口の上限 (住みやすさ)・忠誠度・交易の取引費用に効く (どれにするかは決める必要がある)。
- **研究**: 第三次産業の一部として研究者を置き、アイデアの生産関数 (Jones 1995: アイデアの増え方 ∝ 研究者^λ × アイデアの量^φ、φ < 1) で技術を伸ばす。研究者 1 人あたりの生産性は下がっていく (Bloom ほか 2020: 年 約 5〜7% 下がる。目標 R11 で再現用データから決める)。技術は生産性・船の効率 (S3 のエネルギーの連鎖)・寿命などに効かせる案。
- **惑星の段階の見せ方**: 所得の帯で「開拓期・工業化期・成熟期・脱工業期」のような段階の名前を出す案 (遊びの柱 C「理由の分かる歴史」のため、段階が変わった理由を内訳で見せる)。

### 決めてもらうこと (S4 を始める前に)

1. 第三次産業が何に効くか (税収・人口の上限・忠誠度・交易のどれか、または全部)。
2. 研究を、国ごとの 1 本の技術にするか、分野 (農業・工業・推進・統治など) に分けるか。
3. 方針 `FOCUS` を残すか (曲線のまわりで寄せる形にするか)、なくして自動に任せるか。
4. 惑星の発展段階の名前を画面に出すか。
5. ゲーム版とシミュレーション版で違える所 (例: シミュレーション版は推定した曲線そのまま、ゲーム版は変化を早める)。

### 先に要る生データ

- GGDC 10 部門データベース (Timmer ほか 2015)・ILOSTAT の部門別就業・世界銀行の 1 人あたり所得 (R10)
- Bloom・Jones・Van Reenen・Webb 2020 の再現用データ (R11)
- 取得スクリプトは `data/fetch/` に、計算は `data/build/` に、`fetch_history.py` と同じ形で作る
