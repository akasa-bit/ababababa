# 並行で進める決まり

セッションを同時にいくつも動かすための決まりです (2026-10-20 のユーザーの決定。`docs/requests/2026-10-20-共通.md` の 共通-1・共通-2)。どのセッションも `docs/session-start.md` の 3 といっしょに、これに従います。

## 1. レーン

同じレーンの中は順番どおりに 1 本ずつ、違うレーンどうしは同時に進めてよい。セッションの番号と中身は `docs/sessions.md`。

| レーン | セッション | 主に触る所 | 始められる条件 |
|---|---|---|---|
| **A 戦争** | 1 → 2 → 3 | AI・戦争・講和のコード (`warsYearly`・`realmsYearly`・`realmsArm`・講和) | いつでも |
| **B 道具** | 4 → 5 → 17 | `tools/`・CI・`PlayLog`・同意の画面・包装 (試合の計算にはなるべく触らない) | いつでも |
| **C 経済** | 6 → 7 → 8 → 9 | 帳簿 (`earn`・支払い)・財政・生産・`FOCUS` | いつでも。ただし 6・7 は帳簿づくりまでにし、つり合いの判断はセッション 4 の道具ができてからにする |
| **D 人口と船** | 10 → 11 → 12 → 13 → 14 | 人口・集団・船の設計・艦隊戦 | A と C が終わってから |
| **E 仕上げ** | 15 → 16 → 18 | つり合い・試遊・文字列 | D が終わってから。**18 (文字列を集める) は全部のファイルに触るので、ほかのレーンが止まっているときに 1 本だけで回す** |

- レーンの「主に触る所」の外を大きく直すときは、PR の本文にそう書き、ほかのレーンで動いているセッションに響かないか確かめる。
- 1 つのレーンを 2 つのセッションで同時に進めない。

## 2. 文書の分け方 (衝突しないように)

全員が書き足すファイルを作らない。

| 何を | どこに | 決まり |
|---|---|---|
| ユーザーの依頼 (そのまま) | `docs/requests/<日付>-<レーン>.md` (例: `2026-10-21-A.md`) | 番号は `<レーン>-<通し番号>` (例: A-1)。通し番号はそのファイルの中だけで数える。並行の前の依頼は `docs/requests-log.md` (1〜137。セッション 1 が足す分まで) |
| レーンのいまの状態と次にやること | `docs/status/<レーン>.md` | そのレーンのセッションだけが書く |
| 止めている作業の差分 | `docs/wip/<レーン>-<名前>.patch` | 書いたら `docs/status/<レーン>.md` に載せる |
| 全レーンに共通の約束・文書の地図・作業のこつ | `docs/handoff.md` | 共通の決まりが変わるときだけ直す (いまの状態は書かない) |
| 段取り・補正の台帳 | `docs/game-plan.md` | 段が終わったときと、台帳に行を足すときだけ。足すときは表の末尾に 1 行ずつ (並べ替えない) |

レーンに入らない相談 (段取りや決まりの話) は、レーン名を `共通` にする (`docs/requests/<日付>-共通.md`・`docs/status/共通.md`)。

## 3. マージの前

1. main を取り込む (`git fetch origin main && git merge origin/main`)。
2. `index.html` (組み立てたもの) が衝突したら、手で直さず `node tools/build.mjs` で作り直す。
3. `node tools/ci-tests.js` を通してから push し、**CI をもう一度回す**。自動対戦の表は main と比べるので、main が動いたあとの表でないと当てにならない。
4. 新しい表がすべて合格になってからマージする (マージはユーザーの許可を待たない)。
5. 目標 (`targets/targets.json`・`targets.lock`) を変える PR は、ほかのレーンに同じものが開いていないか確かめ、1 本ずつ出す。
6. PR は小さく、早めにマージする (長く開けておくほど衝突が増える)。

GitHub の設定 (branch protection の *Require branches to be up to date before merging*) をオンにすると、1 を忘れても GitHub が止めてくれる (ユーザーの設定)。

## 4. 始め方

- レーンごとに Claude Code のセッションを 1 つずつ開き、`docs/sessions.md` の 4 にある、そのセッションの文を送る。
- 文の終わりに、ほかに動いているレーンを書き足す (例:「いま A と C も並行で動いている」)。

## 5. 並行に移るときの後片付け

セッション 1 (レーン A) は、並行の決まりの前に始まったので、前の形 (`docs/handoff.md` と `docs/requests-log.md`) に書く。そのままでよい。
セッション 1 のマージのあと、レーン A の次のセッション (セッション 2) の最初に、次の片付けをする。

- `docs/handoff.md` の「3. いまの状態」「5-3. 止めている作業」の中身を、`docs/status/A.md`・`docs/status/C.md` (財政の差分) などに移し、`handoff.md` には共通の約束と地図だけを残す。
- `docs/requests-log.md` の頭に「ここで終わり。続きは `docs/requests/`」と書く。
- `fiscal.patch` は `docs/wip/C-fiscal.patch` に名前を変える (中身はそのまま)。
