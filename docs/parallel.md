## 2. コードの場所の持ち主 (地図)

- **`src/` のファイルの一覧と持ち主は `docs/src-files.md` の 5**。持ち主はフォルダで決まる。自分のレーンのフォルダのファイルだけを直す。前の「〇〇と〇〇は同時に動かさない」という個別の決まりは、これで要らなくなった。
- **`src/core/` は共通の場所** (試合の作り方・1 刻み・セーブ・光の遅れの記録・指令・メインループ)。世話役は道具と検証。ほかのレーンが core を触るのは、次の 2 つに限る:
  1. 登録の形で足す: セーブの項目は `saveField` (`docs/src-files.md` の 2)。
  2. 1 行の呼び出しを足す (年ごとの処理を `advance` から呼ぶ・指令を `exec` に足す など): PR の本文に「core を触る」と書き、触った行を挙げる。同じ時期に core を触る PR は 1 本ずつにする。
- **ほかのレーンの画面の部品**: `politics/panels.js`・`economy/fiscal-ui.js`・`ship/military-ui.js` などは、その仕組みのレーンが持つ。画面と最初の体験は、見た目の決まり (`screen/page.html` の CSS) とタブ・地図・手引きを持ち、ほかのレーンの部品の見た目を変えたいときは、そのレーンに知らせ (`docs/notices/`) を書いて突き合わせる。
- **ほかのレーンのフォルダ** (2026-10-23、W1 の Q3 = a): core と同じ扱いにする。持ち主のレーンが止まっているときは、1 行の呼び出しまで足してよい (PR の本文に書き、持ち主に知らせを置く)。持ち主が動いているときは、自分では触らず、知らせで持ち主に頼む。
- **`src/` に同時に触るのは 3 レーンまで**。どの 3 つかは、その波の始めに `docs/sessions.md` に書く。道具と検証・外向き (`desktop/`・`store/`) は `src/` に触らないので数えない (外向きが `src/outward/` や文字列に触る回は数える)。
- **翻訳の本番** (画面の文字列を 1 か所に集める回) は全部のファイルに触るので、ほかのレーンが止まっている時期に 1 本だけで回す。

## 4. マージの前

1. main を取り込む (`git fetch origin main && git merge origin/main`)。
2. `node tools/ci-tests.js` を通してから push し、**CI をもう一度回す**。自動対戦の表と面白さの代わりの数は main と比べるので、main が動いたあとの表でないと当てにならない。
3. 新しい表がすべて合格になってからマージする (マージはユーザーの許可を待たない)。面白さの代わりの数が大きく悪くなった PR は、マージの前に理由を本文に書く。**止める線** (回 DO2・B-071 で決めた。`tools/fun-report.js` の `STOP`。main と同じ銀河・同じ戦略で比べる):
   - 判断を求められる回数が、main より 25% 以上減る
   - 待つだけの年の割合が、main より 10 点以上増える
   - いちばん多く勝った戦略の割合が 75% 以上になり、main より増える
   - 10% 以上の銀河で勝った戦略の数が 2 より少なくなり、main より減る
   - 4 つの成績すべてで他を上回った戦略がいた銀河が 2 以上になり、main より増える
   - 観戦の AI と同じ値の戦略が、どこかの銀河で放任と違う筋になる (`tools/strategy.js` を合わせ直す。どのレーンが直してもよい)

   線を越えると、CI の表の「止める線」に出て、ジョブ「面白さの数の止める線」が失敗する。わざと変えたときは、PR の本文に `面白さの数が悪くなった理由: …` の行を書いて、ジョブを回し直すか次にプッシュする (本文はそのときに読み直すので通る)。必勝法を探す AI の上積みは PR の版だけで回していて main と比べられないので、線にしていない。
4. 目標 (`targets/targets.json`・`targets.lock`) を変える PR は 1 本ずつ。版はマージの直前に main の版に 1 を足す (`docs/registry.md`)。
5. PR は小さく、早めにマージする。**ブランチを積み重ねない** (前の PR のブランチの上に次を作らない。前の PR がマージされた main から始める)。
   - **同じレーンの PR を並べるとき** (2026-10-23、W1 の Q2 = b): 触るファイルが重ならない PR は並べて出してよい。同じファイルを触る PR は 1 本ずつ (前がマージされてから、その main で次を作る)。1 波目に GA4 の 4 本を同じ main から出して、同じファイルが順にぶつかったため。
6. 組み立てた `index.html` はコミットしない (回 R3 から。公開のときに組み立てる)。だから `index.html` の衝突はもう起きない。

### 道具と検証 (DO)

- `tools/` と CI は、ほかのレーンの試験を止めないように変える。新しい試験を CI に足すときは、落ちたら止めるか参考にするかを本文に書く。
- **試験の一覧は、`tools/tests/` に置いたファイルを自動で拾う** (回 DO4・B-221。前は `tools/ci-tests.js` の `TESTS` にみんなが 1 行ずつ書き足して衝突した)。試験を足すレーンは、`tools/tests/<名前>.js` を 1 つ置くだけで、`ci-tests.js` は触らない。CI での回し方と合否は、そのファイルの先頭 (説明のコメントのすぐ下) に書く:

  ```js
  // CI での回し方と合否 (tools/ci-tests.js が拾う。書き方は docs/parallel.md の 7 の道具と検証)
  const J = require('../ci-judge');
  exports.ci = [{ args: ['5', '150'], judge: J.passes('語り手') }];
  if (require.main !== module) return;   // ここから下が試験の本体 (CI が読むときは回さない)
  ```

  - `exports.ci` は配列で、1 つが CI の表の 1 行 (同じファイルを引数を変えて 2 回回すなら 2 つ)。`args` = 引数 (配列か `(c) => 配列`。`c = { root, shots, path }`、`shots` は画面の写しを書く作業場所)、`judge(出力, 終了コード)` = 落ちた理由の文字列 (合格なら空)、`env` = 足す環境変数、`optional: true` = シミュレーション版の試験 (表に「参考」と出し、落ちても止めない)、`needs` = このファイルがなければ回さない。
  - 合否の小道具は `tools/ci-judge.js`: `J.passes('語り手')` = 終了コード 0 で「語り手 合格」が出る、`J.firstLine('R07', 理由)` = 1 行目に「R07 合格」、`J.noPageErrors(出力)`・`J.byJson(良いか, 理由)` (出力の JSON を読む)。
  - `exports.ci` を書かないファイルは、引数なしで回して終了コード 0 なら合格。CI で回さない試験は `exports.ci = false`。
  - 表は名前の順。手元では `node tools/ci-tests.js story` で 1 本だけ回せる。新しい試験は、落ちたら止めるか参考にするかを PR の本文に書く (`optional` を付けない = 止める)。
- 面白さの代わりの数 (`tools/fun-report.js`) と必勝法を探す AI は、観戦の AI (`src/ship/earth-war.js` の `earthWarYearly`) を `tools/strategy.js` に写している。船と戦争がそこを変えたら、`strategy.js` を合わせ直す (どのレーンが直してもよい)。
