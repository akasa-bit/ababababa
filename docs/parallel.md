## 2. コードの場所の持ち主 (地図)

- **`src/` のファイルの一覧と持ち主は `docs/src-files.md` の 5**。持ち主はフォルダで決まる。自分のレーンのフォルダのファイルだけを直す。前の「〇〇と〇〇は同時に動かさない」という個別の決まりは、これで要らなくなった。
- **`src/core/` は共通の場所** (試合の作り方・1 刻み・セーブ・光の遅れの記録・指令・メインループ)。世話役は道具と検証。ほかのレーンが core を触るのは、次の 2 つに限る:
  1. 登録の形で足す: セーブの項目は `saveField` (`docs/src-files.md` の 2)。
  2. 1 行の呼び出しを足す (年ごとの処理を `advance` から呼ぶ・指令を `exec` に足す など): PR の本文に「core を触る」と書き、触った行を挙げる。同じ時期に core を触る PR は 1 本ずつにする。
- **ほかのレーンの画面の部品**: `politics/panels.js`・`economy/fiscal-ui.js`・`ship/military-ui.js` などは、その仕組みのレーンが持つ。画面と最初の体験は、見た目の決まり (`screen/page.html` の CSS) とタブ・地図・手引きを持ち、ほかのレーンの部品の見た目を変えたいときは、そのレーンの状態のファイルに知らせを書いて突き合わせる。
- **`src/` に同時に触るのは 3 レーンまで**。どの 3 つかは、その波の始めに `docs/sessions.md` に書く。道具と検証・外向き (`desktop/`・`store/`) は `src/` に触らないので数えない (外向きが `src/outward/` や文字列に触る回は数える)。
- **翻訳の本番** (画面の文字列を 1 か所に集める回) は全部のファイルに触るので、ほかのレーンが止まっている時期に 1 本だけで回す。

## 4. マージの前

1. main を取り込む (`git fetch origin main && git merge origin/main`)。
2. `node tools/ci-tests.js` を通してから push し、**CI をもう一度回す**。自動対戦の表と面白さの代わりの数は main と比べるので、main が動いたあとの表でないと当てにならない。
3. 新しい表がすべて合格になってからマージする (マージはユーザーの許可を待たない)。面白さの代わりの数が大きく悪くなった PR は、マージの前に理由を本文に書く (止める線は道具と検証が決める。`docs/backlog.md` の B-071)。
4. 目標 (`targets/targets.json`・`targets.lock`) を変える PR は 1 本ずつ。版はマージの直前に main の版に 1 を足す (`docs/registry.md`)。
5. PR は小さく、早めにマージする。**ブランチを積み重ねない** (前の PR のブランチの上に次を作らない。前の PR がマージされた main から始める)。同じ場所を触る回は、同じレーンでも並べない。
6. 組み立てた `index.html` はコミットしない (回 R3 から。公開のときに組み立てる)。だから `index.html` の衝突はもう起きない。

## 5. 始め方

- レーンごとに Claude Code のセッションを 1 つずつ開き、`docs/sessions.md` の 4 にある、その回の文を送る。
- 文の終わりに、ほかに動いているレーンを書き足す (例:「いま GA と SE も並行で動いている」)。
- 1 波が終わったら、common の回で、衝突と取り込み直しの回数と、返事待ちで止まった時間を数えて、組み方を見直す (`docs/restart.md` の 7。`docs/status/common.md` に書く)。

## 6. シミュレーション版は一旦無視する (2026-10-20 から。組み直したあとも続く)

- **船と戦争のほかは、シミュレーション版を無視する。** `simulation.html` を作り直さない・直さない (`node tools/build.mjs` はゲーム版だけを作る。シミュレーション版は `--sim` を付けたときだけ)。
- CI の表の「シミュレーション版・参考」の行は、落ちても CI を止めない。
- 物理の所 (`src/ship/physics.js`・`src/ship/energy.js`、`ED.physics`・`this.physics` を見ている所、`EDITIONS.<版>.physics`) と `EDITIONS.sim` は船と戦争が持つ。ほかのレーンは、`bookShip` などを呼ぶ所を直すときに、航路の長さ `ly` を渡す所・`withAccel` を掛ける所・`this.physics` を渡す所を消さずに残す。シミュレーション版だけの物理は `SIM_ONLY` で分けてある (#173)。
- ゲーム版の物理の切り替え `Game.physics` はセーブに入り、ないセーブは物理なしで読む。

## 7. レーンごとの決まり

### 画面と最初の体験 (GA)

- **これまでの画面の決まりを守る。** `docs/handoff.md` の 15 (スキン 6・額縁の枠・古い報告書風の書体・文字の 4 段階・押したボタンが指から逃げない・説明は「説明」を押したときだけ など) と、`docs/requests-log.md` の画面の依頼。変えたいときは、変える前に表にしてユーザーに選んでもらう (返事待ちは `docs/decisions.md` へ)。
- **アイコンは、候補を見せてユーザーに番号で選んでもらう**。出典とライセンスは README の「アイコンの出典」に足す。
- **PR は画面 1 つずつ、小さく早く。** Xiaomi Pad 8 Pro の横 (1280×780) と縦 (854×1200) で撮り、前と後を並べて PR に書く。画面を操作する試験 (`pick`・`rotate`・`edit`・`home` など) を通す。
- 画面に新しい値を出したいときは、`known` (スナップショット。`src/core/knowledge.js`) に値を足す小さな変更にして、PR の本文に「core を触る」と書く。

### 外向き (SO)

- 包装は、組み立てた `index.html` を外から包むだけにする。ゲームの中身・`tools/build.mjs`・CI は変えない (包装のための変更が要るときは、その所だけを小さな PR にして本文に書く)。
- 包装の組み立てと試験の台本は `desktop/` の中、ストアの文・画像の案・Steamworks の手順は `store/` に置く。
- Steamworks のアカウント・支払い・税の書類など、ユーザーにしかできないことは、手順の一覧にして `docs/decisions.md` の「ユーザーにしかできないこと」に足す。代わりに登録しない。

### 道具と検証 (DO)

- `tools/` と CI は、ほかのレーンの試験を止めないように変える。新しい試験を CI に足すときは、落ちたら止めるか参考にするかを本文に書く。
- 面白さの代わりの数 (`tools/fun-report.js`) と必勝法を探す AI は、観戦の AI (`src/ship/earth-war.js` の `earthWarYearly`) を `tools/strategy.js` に写している。船と戦争がそこを変えたら、`strategy.js` を合わせ直す (どのレーンが直してもよい)。
