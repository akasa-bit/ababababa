# ゲーム版を先に仕上げる段取り

2026-10-18 にユーザーが決めたこと (`docs/requests-log.md` の 130) と、監査 A (`docs/audit-A.md`) のあとの進め方です。

## 1. 決めたこと

- **まずゲーム版だけを作る。** シミュレーション版は、ゲーム版を公開したあとで作る。それまでは**一切編集しない**。
  - `node tools/build.mjs` はゲーム版 (`index.html`) だけを作る。`simulation.html` は #107 のあとの形のまま凍結し、組み立て直さない。
  - `src/index.html` の `EDITIONS.sim` の値も変えない。シミュレーション版を作り直すときは、そのときの `src/index.html` から組み立て、版の違いを測り直す。
- **ゲーム版の物理は軽くてよい。** 完全に無視はせず、フレーバー (説明文と小さな効き目) として入れる。
- **監査 A の表の 6・9〜13 (0.95c の代償・単位の検査・廃熱と赤外線・回折・M 型星のフレア・R18) は、ほかの物理の話とまとめて、シミュレーション版を作るときのやることに回す** (下の 3)。
- **ライセンス系 (表の 20・G6) も、いったん置く。**
- それ以外は、監査 A のおすすめどおりに進める。

### 監査 A の「選んでもらうこと」の扱い (おすすめで進める。あとで変えられる)

| # | おすすめ (このまま進める) | 理由 |
|---|---|---|
| G2 (R01) | ゲーム版では交易の仕組みを今のまま使い、R01 の合否はシミュレーション版で扱う | ゲーム版で交易が近場に寄ることは、遊びの上では困っていない |
| G3 (年齢と 1 世代 100 年) | ゲーム版は寿命を延ばした設定のまま、年齢を 3 つの区分で持つ。区分の長さは 1 世代 100 年に合わせる | 「1 世代 100 年」はゲーム版で決めたこと。現実の生命表はシミュレーション版で使う |
| G4 (AI にも光の遅れ) | ゲーム版でも AI は古い情報で判断する。弱くなる分は難しさの値で補う | プレイヤーだけが不利な今の形は、遊びとして不公平で、遠い前線の読み合いも生まれない |
| G1・G5・G7 | シミュレーション版のときに選んでもらう (物理と星の分布の話なので) | |

どれも、その段の PR で「ずらした量と理由」を書き、変えたいときに 1 つの値で戻せるようにする。
