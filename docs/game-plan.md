# ゲーム版を先に仕上げる段取り

2026-10-18 にユーザーが決めたこと (`docs/requests-log.md` の 130) と、監査 A (`docs/audit-A.md`) のあとの進め方です。2026-10-20 に、作業を「物理」「社会」「ゲーム性の補正」の 3 つの区分に分けた (requests-log の 132)。

## 1. 決めたこと

- **まずゲーム版だけを作る。** シミュレーション版は、ゲーム版を公開したあとで作る。それまでは**一切編集しない**。
  - `node tools/build.mjs` はゲーム版 (`index.html`) だけを作る。`simulation.html` は #107 のあとの形のまま凍結し、組み立て直さない。
  - `src/index.html` の `EDITIONS.sim` の値も変えない。シミュレーション版を作り直すときは、そのときの `src/index.html` から組み立て、版の違いを測り直す。
- **ゲーム版の物理は軽くてよい。** 完全に無視はせず、フレーバー (説明文と小さな効き目) として入れる。
- **監査 A の表の 6・9〜13 (0.95c の代償・単位の検査・廃熱と赤外線・回折・M 型星のフレア・R18) は、ほかの物理の話とまとめて、シミュレーション版を作るときのやることに回す** (下の 6)。
- **ライセンス系 (表の 20・G6) も、いったん置く。**
- それ以外は、監査 A のおすすめどおりに進める。

## 2. 3 つの区分

仕組みは「何に照らして正しいか」で 3 つに分ける。1 つの段に 2 つ以上の区分が入るときは、PR の本文で区分ごとに分けて書く。

| 区分 | 何に照らして正しいか | 合否の決め方 | ゲーム版での扱い |
|---|---|---|---|
| **物理** | 物理法則・保存則・単位 | 式との差・保存の誤差の試験 (R03・R07 など) | フレーバー (説明文と小さな効き目)。重いものはシミュレーション版に回す |
| **社会** | 歴史と観測の実データ・社会科学の理論 | 合わせる目標 (`targets/targets.json` の R 系) | 正しく作る。ずらすときは補正の層で |
| **ゲーム性の補正** | 面白さ・分かりやすさ・つり合い | 試遊と自動対戦の目標 (F 系)、ユーザーの判断 | 下の 4 の台帳に載せたものだけ |

決まり:

- **補正は、物理と社会の式の中に混ぜない。** 正しい値で計算した上に掛ける、別の値として持つ。外せば「補正なし」(シミュレーション版のもと) に戻ること。
- **補正の値は `EDITIONS.game` に置く。** `EDITIONS.sim` は凍結中なので触らない。新しい補正を足すときは、コードの側で「値がないときは補正なし (現実の値)」になるように書く (例: `ED.foo ?? 1`)。こうすれば `EDITIONS.sim` を変えずに済み、シミュレーション版は補正なしになる。
- **補正を足す・変えるときは、下の 4 の台帳に 1 行足す** (現実の値・ゲーム版の値・理由・戻し方)。台帳にない補正は入れない。
- **「まだ正しくない」と「わざとずらした」を分ける。** 正しく作れていないもの (R01・R14 など) は補正ではないので、台帳ではなく下の 5 に書く。
- ずれがユーザーの選ぶことなら (「現実的」と「面白い」のぶつかり)、これまでどおり、ずらした量と理由の表にしてユーザーに選んでもらう。
