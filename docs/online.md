# アカウントとオンライン (Firebase)

ホーム画面の「アカウント」タブで、Firebase のアカウントにログインできます。ログインすると、次のことができます。

- **クラウドのセーブ**: いまのゲームをアカウントに保存し、別の端末でロードする。
- **自作の国**: 国家づくりで作った国を、アカウントに送る・アカウントから足す。
- **招待コードでネット対戦**: ホストがネット対戦の部屋を作ると 4 文字の招待コード (英字と数字) が出る。参加する人は、そのコードを入れると部屋に入り、動かす国を自分で選ぶ。
  **これだけはログインが要らない** (どちらも、ログインしていなければゲストとして自動で入る)。下の 3 と 4 に詳しく。前からの「長い招待コードと返事コードを手で渡す」方法は、予備として残してある。

## 1. Firebase の準備 (はじめに 1 回だけ)

1. [Firebase のコンソール](https://console.firebase.google.com/) で、プロジェクトを作る。
2. 「Authentication」→「Sign-in method」で、次の 3 つをオンにする。
   - Google
   - メール/パスワード
   - 匿名 (ゲスト用)
3. 「Authentication」→「設定」→「承認済みドメイン」に `akasa-bit.github.io` を足す (GitHub Pages で遊ぶため)。
4. 「Firestore Database」を作り、「ルール」にリポジトリの `firestore.rules` の中身を貼って公開する。
5. 「プロジェクトの設定」→「マイアプリ」でウェブアプリを足し、`firebaseConfig` (apiKey・authDomain・projectId・appId など) を写す。
6. 写した設定を次のどちらかに入れる。
   - **みんなが使えるようにする**: `src/outward/cloud.js` の `FIREBASE_CONFIG` に書いて、組み立て直す (`node tools/build.mjs`)。ウェブアプリの apiKey は公開してよい値。守るのは Firestore のルールの役目です。
   - **この端末だけで試す**: ホーム画面の「アカウント」タブの「Firebase の設定」に、JSON のまま貼って「設定を使う」。

## 2. 仕組み

| もの | Firestore の場所 | 中身 |
|---|---|---|
| 名前 | `users/{uid}` | ネット対戦で相手に見せる名前 |
| クラウドのセーブ | `users/{uid}/saves/{id}` と `…/parts/{n}` | 一覧に出す情報 (年・星系の数・銀河・版)。セーブ本体は詰めて (deflate)、70 万字ずつの文書に分ける (Firestore の文書は 1 MiB まで) |
| 自作の国 | `users/{uid}/data/nations` | 国家の保管庫の一覧 |
| 部屋 | `rooms/{招待コード}` | ホスト・版・席の一覧・作った時刻。始めたあとも開いている (遅れて来た人・切れた人が同じ招待コードで入れる)。ホストが閉じる・作り直すと消える (招待コードが空く) |
| 席 | `rooms/{招待コード}/seats/{口の番号}` | つながる口 (国とは別)。ホストの招待 (WebRTC の offer)、席を取った人の uid と名前、返事 (answer)。どの国を動かすかは、つながったあとに部屋の中で選ぶ (4) |

- ネット対戦の中身 (命令の受け渡し・状態の合わせ直し) は前と同じで、WebRTC でつないだ端末どうしが直接やりとりする。Firebase は、つなぐときの情報の受け渡しと、アカウントの保存だけに使う。
- Firebase の JS は、アカウントの機能を使うときだけ、Google の配信 (gstatic.com) から読みこむ (ゲームのファイルは大きくならない)。
- 設定が入っていなければ、アカウントの機能は出さず、前と同じように遊べる。

## 3. 招待コード (4 文字) でつなぐ

2026-11-10 のユーザーの依頼 (`docs/requests/2026-11-10-common.md` の common-1「Firebaseの接続もっと簡単にして」・common-2「送る招待コードを4桁のアルファベットと数字にしろ」) で作り直した。
前は、ホストも参加する人も先に「アカウント」の頁でログインし、ホストが「部屋を作る」を押して 6 文字の「部屋のコード」を出していた。ログインしていないと、長いコードを手で渡す方法しか画面に出なかった。

| | 前 | いま |
|---|---|---|
| ホスト | アカウントの頁でログイン → ネット対戦の画面 →「部屋を作る」→ 6 文字のコード | 国家選択で「ネット対戦」を押すだけ。4 文字の招待コードが自動で出る (「コピー」で写せる) |
| 参加する人 | アカウントの頁で「ゲストではじめる」→「参加する」→「部屋に入る」に 6 文字 | 「参加する」→ 招待コード 4 文字と名前を入れて「参加する」(Enter でもよい) |
| ログイン | 先に自分でする | しなくてよい。していなければゲスト (Firebase の匿名ログイン) として自動で入る。前からのログイン (Google・メール) があれば、そのアカウントのまま |
| 長いコードの手渡し | いつも画面に出る | 予備。ホストは「長いコードを手で渡してつなぐ」で切りかえ、参加する人は同じ名前のたたんだ欄を開く。オンラインの部屋が使えないとき (つながらない・ゲストのログインが止められている) は、理由を出してこの方法を案内する |

- **招待コード** (`outward/cloud.js` の `roomCode`): 4 文字。英字 (大文字) と数字を必ず 1 つずつ入れる。見間違えやすい I・L・O・0・1 と、たまたま言葉になるのを避けて母音 A・E・U は使わない。
  英字 20・数字 8 の 28 字から 28⁴ − 20⁴ − 8⁴ = **450,560 通り** (Python で数え、英字の数ごとの足し算で検算)。入れるときは小文字でも、前後に空白があってもよい。
- **同じコードがもう使われていたら** (`freeCode`): 別のコードを引き直す (ほかの人の部屋は Firestore の決まりで書きかえられない。12 回まで)。
- **期限** (`ROOM_TTL`): 作ってから 1 日たった部屋には入れない (始める前にタブを閉じて閉じ損ねた部屋に、あとから間違って入らないように)。
- **掃除**: 始める前に閉じたら・作り直したら、ホストが部屋と席を消す (`dropRoom`。先に `open: false` にしてから、席 → 部屋の順)。閉じ損ねた自分の部屋 (試合が終わってタブを閉じた部屋も) は、次に部屋を作るときに消す (`dropStale`。端末に最後のコードを覚えておく)。
- **つながらなかった・抜けた人の席**: ホストが同じ招待コードのまま、その席に新しい招待を置き直す (`reseat`。返事が読めなかった席も。始める前も、試合の途中も)。相手は同じコードで入り直せる。
  ホストの「コードを作り直す」は、まだだれも入っていない席だけを新しいコードで出し直す (入っている人はそのまま)。そのあとで、入っていた人が抜けたら、いまの部屋に席を足す (部屋がもうなければ、新しい招待コードを作る)。
  相手が落ちたことには、つながりが切れた知らせ (15〜30 秒) で気づく (前は、始める前だとデータチャネルが開いたまま残って「つながった」と出続けることがあった)。
- **席の招待がそろってから招待コードを見せる**: 前はコードが先に出て、すぐ入れた人が「あいている席がない」になることがあった。席の招待は同時に作る (前は 1 つずつ。1 つ最大 4 秒)。
- **Firestore の決まり (`firestore.rules`) は変えていない**: 部屋を作る・消すのはホストだけ、席を取れるのは空いている席だけ、のまま。Firebase のコンソールでの作業は要らない (匿名ログインは 1 の 2 でオンにしてあるもの)。
- **4 文字にしたことの見切り**: 6 文字 (31⁶ ≒ 8.9 億通り) より当てやすい。開いている部屋が 10 あるとき、でたらめなコード 1 つが当たるのは 45,056 回に 1 回。部屋は始めると消え、1 日で期限が切れ、
  知らない人が席に入ってもホストの画面に名前が出て、「コードを作り直す」で出し直せる。友達どうしで遊ぶ分には足りると見た (公開して人が増えたら、文字数を `ROOM_LEN` で増やせる)。
- **自動の試験は本物の Firebase に触れない** (`CLOUD_ROBOT`): 画面を開くだけで部屋を作りゲストでログインするようになったので、自動操作のブラウザ (`navigator.webdriver`。Playwright の試験) では、
  偽物 (`window.__FB_FAKE`) を差しこんだときだけオンラインの機能を出す。差しこまない試験 (`tools/tests/net.js` など) は、長いコードの方法だけの画面になる。

## 4. 部屋 (HoI4 式): 国は、部屋に入ってから参加者が選ぶ

2026-11-10 のユーザーの依頼 common-3「Hoi４のマルチを参考に、招待コードが必要なのは部屋にはいるだけにして、どの国を選ぶのかは参加者が選べるようにして」(`outward/net.js`)。

| | 前 | いま |
|---|---|---|
| だれがどの国か | ホストが国家選択で友達の国を「＋人間」にしておく。招待コードを入れた人は、空いている席に先着で入る (国は選べない) | ホストは自分の国だけを決めて「ネット対戦の部屋を作る」。参加者は部屋に入ってから、国の一覧で「この国にする」(ホストが始めるまで変えられる) |
| つながる口 | 国ごと (招待はその国の席のもの) | 国とは別 (`Net.slots`。国の数 − 1)。招待コードでも長いコードでも、つながると同じ部屋に入る |
| 始めるとき | 「＋人間」にした国のうち、つながっていない国を AI に任せる | 選ばれた国 (とホストの国) だけを人間の席にして、席を作り直す (`setPlayers`。どの人も同じ初期値。ほかの国は AI の席) |
| 遅れて来た人・切れた人 | ホストが「入っていない国」の招待を作り直す (その国にだけ戻れる) | 同じ招待コードで部屋に入り、AI が動かしている国を選ぶと、その国ですぐ入る (途中参加。人が動かしたことのない国でもよい) |
| 部屋 | 始めたら消える | 始めたあとも開いている。ホストは部屋にいる人を「外す」ことができる |

- **部屋のやりとり** (データチャネル): 参加者 → `hello` (名前)・`pick` (選んだ国。やめるときは null)。ホスト → `lobby` (国の一覧と、だれが選んだか。試合が始まっているか)・`bye` (部屋から外した)。
  国を決めるのはホスト (`takePick`): ホストの国・ほかの人が選んだ国・もう国ではない国 (滅んだ・従属した) は断り、理由を付けて一覧を送り直す。
- **選ぶ手がかり**: 参加者の国の行には、種族・首都のある星系・人口・星系の数・難しさの目安 (★ 1〜3)・特性の名前と効き目が出る。
  数字はホストの試合のもの (`nationList` が `lobby` に入れて送る。参加者の手元の試合は、始まるまで別物なので使わない)。途中参加のときは、そのときの人口と星系の数になる。
  難しさの目安は、国家選択のカードと同じ数え方 (`screen/nation-pick.js` の `nationRating`: 近い国の数・開始の大きさ・地球かどうか)。もう国ではない国の行には出さない。
- **始めるとき** (`start`): 国家選択から開いた、まだ始めていない試合 (`fresh`) は、選ばれた国で `setPlayers` をやり直す (「歩みはじめた」の知らせもこのとき)。
  続きの試合 (セーブを読んだ・ひとりで遊んでいた試合に人を呼ぶ「ホストになる」) は、席はそのままで、選ばれた国を人の手に、選ばれなかった人間の席を AI に任せる。
  国を選んでいない人は部屋に残り、始まったあとに AI の国を選べば入れる。
- **途中参加** (`hotJoin`): いまの状態を送り、次のコマでその国を人の手に渡す (命令 `rejoin`。前からある「切れた人が戻る」と同じ道)。AI の席 (`addAiSeats`) も、人の席と同じ項目を持つので、そのまま人が動かせる。
- **切れた人** (`lost`): その国は AI に任せ (命令 `drop`)、口は空く。招待コードの部屋なら、その口に新しい招待が置き直されるので、同じコードで入り直して同じ国を選べば戻れる。
- **ホストになる** (ホーム → マルチプレイ): 国が 2 つ以上ある、いまのゲームに人を呼ぶ (前は、人間の席が 2 つ以上ある試合だけ)。入った人は、AI が動かしている国 (か、前に自分が動かしていた国) を選ぶ。
- 体験版には「ネット対戦の部屋を作る」を出さない (体験版はマルチプレイの頁がなく、参加もできない)。

## 5. 試験

`tools/tests/cloud.js` は、本物の Firebase の代わりに、同じ形の偽物 (データは試験の側に置く) を差しこんで確かめる。

- ゲストでのログインと名前
- クラウドのセーブの保存・ロード・削除
- 自作の国を送る・足す
- 招待コードで 2 つの端末がつながり、ネット対戦の状態の要約が一致すること。ホストも参加者もログインしないで始め、ゲストとして自動で入ること。参加者の入れた名前がホストの画面に出ること
- 部屋: つながる口が国の数 − 1 あること。参加者が国の一覧から選び、選び直せること。ホストの国は選べないこと。ホストの画面に名前と選んだ国が出ること。始めると、選ばれた国だけが人間の席になること。参加者の国の行に、選ぶ手がかり (首都・人口・星系の数・難しさの目安・特性の効き目) がホストの試合の数字で出ること
- 招待コードが 4 文字で、英字と数字が必ず混ざり、使わない字 (I・L・O・0・1・A・E・U) が入らないこと (300 個作って見る)。同じコードの部屋がもうあれば別のコードになり、その部屋は書きかえないこと
- ない部屋・期限の切れた部屋・字数の違うコードには入れず、理由が画面に出ること。小文字と空白まじり・Enter でも入れること
- 始める前に参加者のタブが閉じたら、ホストが同じ招待コードのまま席に新しい招待を置き直し、別の端末が同じコードで入れること
- 始めたあとも部屋が開いていること
- 試合の途中で参加者のタブが閉じたあと、新しく開いた参加者が同じ招待コードで部屋に入り、同じ国を選んで戻り、要約が一致すること (回 SO5 の作り直し)。前からメールでログインしていた人は、ゲストに切りかわらないこと
- 遅れて来た人が、同じ招待コードで部屋に入り、人が動かしたことのない AI の国を選んで途中から入り、3 台の要約が一致すること。ほかの人が動かしている国は選べないこと
- 偽物を差しこんでいない自動操作のページは、Firebase の JS も読まず、ネット対戦の画面は長いコードの方法だけになること

本物の Firebase (ログインの画面やルール) は、準備が終わってから実機で確かめる。
